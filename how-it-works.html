ARCHITECTURE

How AEGIS Works

A zero-hardware mesh turns observations from existing sky-watchers into a shared, time-aware view of the night sky. Each participant keeps their current setup; AEGIS coordinates, checks, and combines eligible observations.

Explore the pipeline ↓

01 / Observation pipeline

From local frame to shared context

Four straightforward stages connect independent observations without requiring a new sensor network.

01

Local capture

An existing telescope or sky camera records a frame at its own site. A participant can contribute with equipment they already use; AEGIS does not imply a new hardware installation.

02

Trend detection

Frame metadata and observations can be compared over time to surface changes worth reviewing. A trend is a signal for further checking, not proof of a discovery by itself.

03

Coordinate alignment

Plate-solving maps a frame onto shared celestial coordinates, so observations from different locations can be compared in the same reference system. Alignment quality still needs to be checked before combining data.

04

4-day sliding window

Eligible observations are merged across a rolling four-day window to balance freshness with opportunities for coverage. As a new day enters, the oldest slice rolls out.

06 / Honest boundaries

Questions, answered plainly

AEGIS is a project concept. The interactive checks below are not evidence of a deployed production network.

Why a 4-day window?

It is a tunable design parameter intended to balance freshness against coverage. Four days is not a proven optimum; a production system would need to evaluate different windows against real observation quality and latency.

What if no nodes are clear?

There may be no eligible observation for that region and time. A system should report the coverage gap or wait for clearer data rather than imply that a neighbor can always replace the missing view.

How are frames verified?

This demo illustrates cloud and radiance checks using the same deterministic accept/reject rule as the project data module. A production pipeline would also need validated plate-solving, provenance, quality controls, and live data integration; this page does not perform those operations.

Do I need new hardware?

The concept is designed around observations from equipment participants already have, such as a telescope or sky camera. It does not require new hardware in principle, although a real contribution flow would depend on supported equipment and data formats.
